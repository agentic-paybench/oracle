# Capability signer (Day-0, dev key)

Offline signer for the Tier-2 capability credentials. Uses an off-the-shelf JOSE
library (`jose`); no hand-rolled crypto.

- **Curve:** ECDSA P-256 only (ES256). AP2 v0.2 mandates P-256 and forbids Ed25519.
- **Key:** a NON-PRODUCTION dev key generated by `keygen.mjs` into `.dev-keys/`
  (gitignored, never committed). Rotate to a hardware PIV P-256 key at the maintainer
  ceremony; same curve, so it is a key rotation, not a rework.
- **Securing mechanism:** VCDM 2.0 Enveloped Verifiable Credentials (VC-JOSE).
  Data Integrity (`ecdsa-rdfc-2019`) is the alternative for the hardware ceremony.

## Verify what is published (no keys needed)

The committed credentials under `docs/site/capabilities/` verify against the
published DID key as-is; you do not need to generate anything:

```
npm ci && node verify.mjs
```

## Maintainer build flow (rebuilding and re-signing)

```
npm install
node keygen.mjs                       # dev P-256 key + docs/site/.well-known/did.json
python ../build_capabilities.py       # unsigned VCs -> ingest/build/capabilities/
node sign.mjs                          # signed enveloped VCs -> docs/site/capabilities/
node verify.mjs                        # CI check: all verify under the DID P-256 key
```

Production credentials are hardware-signed only; the dev key here is for Day-0
demonstration and is clearly labelled non-production in the DID document.
